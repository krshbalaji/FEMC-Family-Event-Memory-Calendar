# FEMC R4.1 — Practice-First External Entry Contract

## Purpose

The external-trial deployment must behave like a usable FEMC Practice application, not like a developer test harness.

## Participant Experience

A fresh external-trial open must produce:

`OPEN FEMC → PRACTICE MODE ACTIVE → EXPLORE NATURALLY`

The participant must **not** be required to click:

- Start Trial
- Reset State
- Trial Session

The visible UI should expose a concise safety indicator such as:

> **PRACTICE MODE** — Explore FEMC safely. Practice actions do not affect your real family data.

## Internal Controls

The existing trial start/exit/reset APIs may remain available for QA, development, automated testing, and controlled recovery. They must not be hidden prerequisites for participant entry.

## Fresh-Entry Initialization

On first external-trial load, initialization must ensure all required state exists:

1. active session
2. Learn-By-Doing / Practice mode
3. Practice World
4. Trial Observer
5. permitted Practice seed data
6. visible Practice Mode state

Initialization must be idempotent. Repeated page loads must not duplicate:

- trial sessions
- practice members
- practice events
- practice memories
- practice media

## Acceptance

Fresh process/state:

1. Open the external-trial application.
2. Do **not** click Reset State.
3. Do **not** click Start Trial.
4. Practice Mode is already active.
5. Practice data is visible.
6. Navigation and normal user actions work immediately.

A participant who only opens the trial link must be able to begin exploring without knowing anything about the underlying trial machinery.

## Regression Guard

The browser acceptance sequence must explicitly include:

`fresh launch → Practice Mode active`

before testing Memory, Media, Calendar, Celebrations, Sharing, Mayil, VEL Guardian, or other Practice flows.

No R4.1 GREEN verdict is valid if a Reset State or Start Trial action is required to make a fresh external-trial session usable.
