# FEMC Privileged Access Architecture

**Version:** 1.0.0
**Status:** Architecture
**Owner:** Architecture Office

## Purpose

Separate operational authority from ordinary family participation.

## Privileged Classes

Conceptually distinguish:

- family participant;
- family steward/delegate;
- support operator;
- security operator;
- system operator;
- service identity.

## Rules

1. Privileged access is explicit.
2. Privileged access is limited by purpose.
3. Sensitive operations are attributable.
4. Emergency access is exceptional and reviewable.
5. Operational privilege does not automatically imply unrestricted family-content access.

## Principle

Running FEMC is not the same as owning a family's memories.
