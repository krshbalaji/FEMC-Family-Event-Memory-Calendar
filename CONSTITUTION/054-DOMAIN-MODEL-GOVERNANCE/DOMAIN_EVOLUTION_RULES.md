# FEMC Domain Evolution Rules

**Version:** 1.0.0  
**Status:** Foundation  
**Owner:** Chief Product Architect

## 1. Add Carefully

New domain concepts should solve a demonstrated product need.

## 2. Avoid Synonyms as Entities

Do not create separate canonical concepts merely because different interfaces use different words.

## 3. Preserve History

Domain evolution must not destroy historical meaning.

## 4. Compatibility

New domain concepts should consider how existing family records remain understandable.

## 5. Migration

A domain change requiring data transformation must define its migration implications before implementation.

## 6. AI

AI-generated concepts or classifications remain derived until appropriately governed.

## 7. Documentation

Material domain changes require durable documentation.

## 8. Principle

The domain should become richer over time without becoming conceptually unstable.
