# FEMC Family Journeys

**Version:** 1.0.0  
**Status:** Foundation  
**Owner:** Chief Product Architect

## Purpose

Define durable family journeys before defining screens or implementation workflows.

## Journey 1 — Remember

A family member wants to find something meaningful from the past.

Conceptual path:

**Person / Event / Time / Relationship → Discovery → Memory → Media / Story**

The experience should minimize searching effort while preserving context.

## Journey 2 — Celebrate

A meaningful occasion is approaching.

Conceptual path:

**People + Event + History → Preparation → Communication → Celebration → New Memory**

The new experience should naturally connect back to the family record.

## Journey 3 — Capture

Something meaningful has happened.

Conceptual path:

**Experience → Memory → People / Relationships → Event / Time → Media → Preservation**

The platform should make memory capture simple enough that families actually use it.

## Journey 4 — Understand Family History

A person wants to understand how the family is connected or what happened across generations.

Conceptual path:

**People → Relationships → Events → Memories → Timeline / Story → Legacy**

## Journey 5 — Share

A person wants to share something with selected family members.

Conceptual path:

**Memory / Event / Media → Permission → Selected People → Communication**

Sharing must not weaken the underlying privacy model.

## Journey 6 — Preserve

A family wants to protect its history for the future.

Conceptual path:

**Family Record → Integrity → Organization → Export / Archive → Generational Continuity**

## Journey 7 — Ask AI

A family member asks FEMC for help.

Conceptual path:

**Identity → Permission → Purpose → Relevant Context → AI Assistance → Result → Human Decision**

AI should assist the journey rather than become the destination.

## Journey Principle

Journeys are more important than screens.

Screens may change.

The family outcome should remain stable.
