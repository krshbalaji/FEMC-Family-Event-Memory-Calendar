# FEMC Experience Integration Rules

**Version:** 1.0.0  
**Status:** Foundation  
**Owner:** Chief Product Architect

## Rule 1 — One Context

A user should not have to reconstruct family context separately in every capability.

## Rule 2 — Follow Relationships

Where relevant, navigation should allow movement through meaningful relationships.

Example:

**Person → Relationship → Event → Memory → Media**

## Rule 3 — Preserve Origin

When information is surfaced in a different experience, its underlying domain meaning must remain intact.

## Rule 4 — Do Not Duplicate Truth

A calendar screen, album screen, family-tree screen, and AI conversation may present the same family information differently.

They must not create separate authoritative copies.

## Rule 5 — Respect Permission

Experience-level convenience must never bypass domain-level permissions.

## Rule 6 — Minimize Friction

The shortest useful path should be preferred when it does not weaken trust, integrity, or clarity.

## Rule 7 — Contextual Assistance

Recommendations and shortcuts should be based on relevant family context, not engagement optimization.

## Rule 8 — Human Confirmation

Actions that materially change family history should have appropriate human control.

## Rule 9 — Graceful Evolution

A new interface should be able to use the existing family model without forcing the family to migrate its meaning into the new interface.

## Rule 10 — Offline and Intermittent Reality

Where appropriate, future experience design should consider families operating with limited connectivity or across different device environments without weakening data integrity.
