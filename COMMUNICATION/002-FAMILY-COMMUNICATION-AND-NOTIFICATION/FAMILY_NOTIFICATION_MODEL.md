# FEMC Family Notification Model

**Version:** 1.0.0
**Status:** Communication Architecture
**Owner:** Communication Office

## Notification Classes

- critical;
- important;
- useful;
- informational;
- optional;
- celebratory.

## Rules

Every notification should have:

- purpose;
- intended recipient;
- triggering context;
- priority;
- delivery expectation;
- preference handling;
- expiry or relevance boundary where appropriate.

Avoid sending a notification simply because an underlying event occurred.

## Principle

An event may exist without requiring a notification.
