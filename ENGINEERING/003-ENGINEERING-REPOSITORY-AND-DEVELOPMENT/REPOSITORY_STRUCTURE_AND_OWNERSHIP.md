# FEMC Repository Structure and Ownership

**Version:** 1.0.0
**Status:** Engineering Architecture
**Owner:** Engineering Office

## Repository Principles

Repositories should make clear:

- what the project contains;
- which area owns each component;
- where documentation lives;
- where tests live;
- where configuration lives;
- how the project is built;
- how changes are verified.

## Ownership

Each material module should have an identifiable technical owner or owning team.

## Rule

Repository structure should reflect meaningful architectural boundaries rather than arbitrary historical growth.

## Principle

A future engineer should be able to understand where a change belongs without reverse-engineering the entire repository.
