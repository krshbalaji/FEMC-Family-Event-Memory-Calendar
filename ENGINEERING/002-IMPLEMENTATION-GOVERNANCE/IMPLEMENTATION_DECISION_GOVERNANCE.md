# FEMC Implementation Decision Governance

**Version:** 1.0.0
**Status:** Engineering Foundation

## Decision Levels

### Local
Formatting, internal refactoring, naming, and implementation details.

### Component
Changes affecting a component's behavior or internal contract.

### System
Changes affecting cross-component behavior, data flows, performance, security, or reliability.

### Architecture Escalation
Changes affecting architectural boundaries, canonical ownership, trust, portability, or major dependencies.

## Rules

1. Record material decisions.
2. Prefer reversible decisions when uncertainty is high.
3. Do not hide architectural changes inside implementation work.
4. Preserve traceability to architecture.
5. Revisit decisions when production evidence changes assumptions.

## Principle

Fast engineering is not undocumented engineering; it is disciplined decision-making with low friction.
